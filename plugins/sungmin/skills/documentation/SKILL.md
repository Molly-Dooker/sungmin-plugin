# 문서 작업 지침

- 별도 지정이 없으면 한글로 쓰고, 코드 identifier·파일명·명령은 원문을 유지한다.
- 작성 전에 대상 소스와 근거를 직접 확인한다. 사실, 해석, 미확인 내용을 구분한다.
- 목적과 결론을 먼저 쓰고 필요한 근거·제약·검증만 덧붙인다. 고정 목차나 불필요한 반복을 만들지 않는다.
- 성능·정확성·안전성 주장은 조건과 검증 근거를 함께 적는다.

## 시각화

중요한 구조, 데이터 흐름이나 상태 전이를 설명할 때는 간결한 ASCII diagram을 함께 제공한다.
`text` code block에서 `+`, `-`, `|`, `<`, `>`, `v`, `^`를 사용해 연결과 방향을 표시한다.
diagram 내부 label은 정렬을 위해 ASCII 영문으로 쓰고, 한글 해설은 밖에 둔다.

```text
+-------+     +---------+     +--------+
| input |---->| process |---->| output |
+-------+     +---------+     +--------+
```

- 사용자 요청 없이 소스 코드, 브랜치, PR, 전달용 patch·로그 묶음·압축 파일을 만들지 않는다.
- 완료 시 변경 파일, 검증 결과, 미실행 항목, commit 여부를 간결하게 보고한다.
