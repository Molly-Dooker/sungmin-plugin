# 작업 공통 원칙

모든 작업에 적용한다. 저장소에 `AGENTS.md`·`CLAUDE.md`가 있으면 함께 따르고, 둘이 다르면 저장소 지침을 우선한다. 문서 저장소 sungmin의 `AGENTS.md`들은 문서 트리와 작성 규칙만 정하며, 그 저장소 문서를 읽거나 쓸 때 함께 따른다.

## 기본 원칙

- 사용자 요청과 현재 저장소 상태를 먼저 확인하고, 추측하지 않는다.
- 관련 구현·호출부·테스트를 읽고 기존 방식에 맞춰 필요한 범위만 변경한다.
- 다른 작업자의 변경을 덮어쓰지 않는다. 브랜치, commit, PR, 전달용 patch·로그 묶음·압축 파일은 요청 없이 만들지 않는다.
- 작업 경로는 PC·계정에 따라 달라질 수 있으므로 특정 절대 경로로 제한하지 않는다. 사용자가 지정한 현재 checkout을 사용하고, `git rev-parse --show-toplevel`과 remote로 대상 저장소를 확인한다.
- commit·push가 요청되거나 작업별 지침으로 허용된 경우, 현재 checkout이 기본 작업 branch(대개 `main`, 작업별 지침이 정한 branch가 있으면 그것. 예: aviron-skills는 `develop`)인지 확인하고 그곳에서 직접 수행한다. worktree(`EnterWorktree`)나 별도 브랜치를 만들지 않는다. 현재 checkout의 실제 권한·편집 제한이 작업을 막으면 우회하지 말고 사용자에게 알린다. 다른 PC의 경로에 접근할 수 없다는 이유만으로 작업을 중단하지 않는다.
- commit 메시지와 PR에는 AI 출처 표기를 넣지 않는다.
- 변경 후 관련 검증을 실행한다. 완료 시 변경 파일, 검증 결과, 실행하지 못한 항목과 실패, commit 여부를 간결하게 보고한다.

## 작업 위치

```text
+---------------------------+   ssh    +------------------------------+
| host                      |--------->| remote server (has device)   |
| - this plugin             |          | - code checkout, build, test |
| - sungmin docs (write)    |<---------| - run, measure, commit/push  |
+---------------------------+  results +------------------------------+
```

- 이 플러그인과 문서 저장소 sungmin은 host에만 있다. 장치가 필요한 실제 작업(빌드, 시험, run, 측정)은 장비가 있는 원격 서버에서 `ssh`로 한다. 서버 접속 방법과 서버별 경로·상태는 sungmin 문서(A0 서버는 `aviron-skills/startingpoint.md` "서버")에서 확인한다.
- 결과 문서와 작업 기록은 host sungmin에 쓴다. 원격 서버에 sungmin 사본을 두거나 거기서 문서를 고치지 않는다. 사용자가 다르게 지시하면 그 지시를 따른다.
- 원격 저장소의 코드 수정과 commit·push는 그 서버의 checkout에서 한다. script, patch, commit 메시지는 host 로컬 파일(작업용 tmp)로 만들어 복사한다. `ssh host '...'` 안에서는 작은따옴표를 쓰지 않는다.
- 문서에는 원격에서 얻은 수치·log·산출물의 서버 이름과 경로를 함께 적는다.
- 샌드박스는 쓰지 않고 대상 장비에서 직접 실행한다. 필요하면 `docker exec` 등으로 그 안에서 실행한다.

## 문서와 기록

- 별도 지정이 없으면 한글로 쓰고, 코드 identifier·파일명·명령은 원문을 유지한다.
- 작성 전에 대상 소스와 근거를 직접 확인한다. 사실, 해석, 미확인 내용을 구분한다.
- 목적과 결론을 먼저 쓰고 필요한 근거·제약·검증만 덧붙인다. 고정 목차나 불필요한 반복을 만들지 않는다.
- 성능·정확성·안전성 주장은 조건과 검증 근거를 함께 적는다.
- 문서 작업에서는 요청 없이 소스 코드를 만들지 않는다.
- 중요한 구조, 데이터 흐름이나 상태 전이는 간결한 ASCII diagram을 함께 쓴다. `text` code block에서 `+`, `-`, `|`, `<`, `>`, `v`, `^`로 연결과 방향을 표시한다. diagram 안 label은 정렬을 위해 ASCII 영문으로 쓰고, 한글 해설은 밖에 둔다.

```text
+-------+     +---------+     +--------+
| input |---->| process |---->| output |
+-------+     +---------+     +--------+
```

## subagent

- 단순 질문이나 짧은 작업은 subagent 없이 직접 한다. 큰 작업에서는 세션이 오케스트레이터로 일을 나눠 맡기고, 결과를 통합·검증해 보고한다. 최종 판단은 부모 책임이다.
- 띄우는 쪽이 조각마다 난이도를 보고 모델과 reasoning effort를 정해 명시한다. 가장 높은 모델을 기계적 기본으로 쓰지 않는다. 애매하면 높은 쪽을 고르고, 결과가 부족하면 한 단계 올린다.
- 세션이 띄운 subagent는 한 단계 더 위임할 수 있고, 그 모델·effort도 띄운 쪽이 정한다. 그 아래는 재위임하지 않는다. subagent는 이 문서를 못 읽을 수 있으므로 지시문에 위임 가능 여부를 적는다.
- 목표, 범위, 관련 경로, 제약, 완료 기준과 검증 방법을 독립적으로 이해할 수 있게 전달한다.
- 긴 결과는 저장소 밖 임시 Markdown 파일로 주고받고, 통합 뒤 정리한다. 짧은 결과는 메시지로 전달한다.
- 쓰기 작업을 병렬화할 때는 파일 소유 범위를 분리한다.
